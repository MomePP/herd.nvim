*herd.txt*                Drive herdr coding agents from Neovim

==============================================================================
INTRODUCTION                                                            *herd*

herd.nvim makes Neovim the top-level UI for your herdr (https://herdr.dev)
coding agents. herdr runs as a background daemon that owns each agent's PTY
— so herdr's status hooks and grouped agent dashboard keep working — while,
in the default "float" mode, agents are shown inside nvim floating
terminals attached via `herdr agent attach`. All navigation uses standard
nvim keybinds; there is no multiplexer round-trip. |herd-native-mode| is
the exception: it has no nvim-hosted window and does use a herdr round-trip
to return to nvim.

Inspired by sidekick.nvim. Where sidekick uses tmux/zellij as the backend,
herd uses herdr — gaining herdr's status hooks and dashboard, with the same
nvim-as-host model (in float mode).

==============================================================================
REQUIREMENTS                                               *herd-requirements*

- Neovim >= 0.10        (uses |getregion()|)
- herdr >= 0.7.5        on $PATH, with a running server
                        (may be a headless daemon; nvim need not run inside
                        a herdr pane)

==============================================================================
SETUP                                                           *herd.setup()*

>lua
    require('herd').setup({
      tools = {
        claude   = { cmd = { 'claude' } },
        opencode = { cmd = { 'opencode', '--continue' } },
      },
    })
<

Options ~                                                       *herd-config*

    tools   table<string, { cmd: string[], env?: table, kind?: string }>
                                                            (default: {})
            Spawnable agents. The key is the tool name; `cmd` is the argv.
            cmd[1] must be a herdr-supported agent kind (see
            `herdr agent start --help`); set `kind` when it is not (e.g. a
            wrapper binary). The rest of `cmd` is passed to the CLI natively.

    mode    'float'|'native'                                (default: "float")
            'float' hosts each agent in an nvim floating terminal (unchanged
            default behavior). 'native' shows it as a sibling herdr tab in
            nvim's own workspace instead, with no nvim window at all —
            requires nvim to run inside a herdr pane; see |herd-native-mode|.
            `win.*` and `keys.hide`/`keys.newline` apply to 'float' only.

    picker  'auto'|'select'                                 (default: "auto")
            Renderer for the GLOBAL agent picker (the native-mode
            dashboard). 'auto' uses snacks.nvim when installed — full
            picker layout with a preview pane showing each agent's
            metadata and live output — falling back to plain vim.ui.select
            otherwise. 'select' forces vim.ui.select even when snacks.nvim
            is installed. The project picker (`keys.select`) always uses
            vim.ui.select.

    keys    { toggle, send, hide, select, dashboard, newline }
            Set any to false to disable. Defaults:
              toggle    = "<leader>\\"      (normal)   toggle agent float; count = slot
              send      = "<leader>\\"      (visual)   send selection
              hide      = "<leader>\\"      (terminal) hide the float
              select    = "<leader>s"       (normal)   grouped picker
              dashboard = "<leader>S"       (normal)   dashboard: float mode focuses the
                                                       herd workspace; native mode opens
                                                       the global cross-project agent
                                                       picker — see |herd-native-mode|
              newline   = "<S-CR>"          (terminal) send CLI newline (Shift-Enter)

    win     { width, height, border, footer, winblend, winhighlight, mouse }
              width        = 1        fraction of &columns (1 = fullscreen)
              height       = 1        fraction of &lines   (1 = fullscreen)
              border       = { '', '', '', '', ' ', ' ', ' ', '' }
                                      invisible border (bottom row kept for footer)
              footer       = true     show "Herd: <agent>" footer
              winblend     = 0
              winhighlight = ""       set terminal-bg highlight groups here
                                      for a transparent overlay (e.g. Snacks:
                                      Normal:SnacksTerminalNormal,...)
              mouse        = true     nvim owns the mouse in the float (the agent
                                      gets scroll/click; Shift+drag to select).
                                      false hands the mouse to the terminal while a
                                      float is focused, so a plain drag selects text
                                      natively — at the cost of the agent's own mouse
                                      inside the float.

    workspace  string                                     (default: "herd.nvim")
               Float mode only: herdr workspace label for spawned agents;
               herd.nvim finds or creates this workspace on each spawn to
               keep agents off your project workspaces/tabs, one labelled
               tab per agent ("<workspace> · <project>" in the sidebar).
               Native mode ignores it — agents land as sibling tabs in
               nvim's own workspace, labelled "<project>:<agent>". In both
               modes herd targets agents by pane id (a bare tool name can
               be ambiguous to herdr).

    send    { context: boolean|fun(ctx): string }  (default: { context = true })
            Visual-send wrapping. true wraps the selection as a
            "path:startline-endline:" header plus a filetype-fenced code
            block, so the agent knows where the code lives. false sends
            the raw selection text (pre-context behavior). A function(ctx)
            formats it yourself, where
            ctx = { path, ft, sline, eline, text } — build on
            `require('herd').format_context(ctx)` if you only want to
            append to the default shape.

    reload  boolean                                       (default: true)
            Run `checktime` when nvim regains focus — and, in float mode,
            on leaving an agent float back to a normal buffer — so buffers
            the agent edited on disk reload instead of going stale.
            Respects 'autoread': silent reload when set, prompt when not.

    auto_return  boolean                                  (default: true)
            Native mode only: after focusing an agent, arm an exit watcher
            (`herdr agent wait`) — if you are still looking at the agent's
            pane when its process ends, focus jumps back to nvim's tab,
            and the now-idle agent tab is reaped (unless you split it).
            false disables both the return and the reaping. Float mode
            auto-closes its float on agent exit regardless.

==============================================================================
MAPPINGS                                                      *herd-mappings*

    <leader>\       (normal)    Toggle this cwd's agent float. <count><key> targets
                                slot N. An empty slot spawns the inferred tool's
                                next clone (inferred: current target's base →
                                first project agent's base → sole configured tool
                                → else picker). Falls back to picker when no
                                agent runs here.
    <leader>\       (visual)    Send selection to the active agent (no Enter
                                appended). The float opens so you can review
                                and submit.
    <leader>\       (terminal)  Hide the float from inside (buffer-local map).
    <leader>s       (normal)    Grouped picker (current project only): switch
                                to a running agent or spawn a configured tool.
                                Rows show "name  [status]".
    <leader>S       (normal)    Dashboard: float mode focuses the dedicated
                                herd.nvim workspace in herdr; native mode opens
                                the global cross-project agent picker (see
                                |herd-native-mode|). Also `:Herd dashboard`.
    <S-CR>          (terminal)  Send a CLI newline (kitty Esc[13;2u) to the
                                agent — buffer-local map for multi-line prompts
                                without submitting.

==============================================================================
PERSISTENCE                                                 *herd-persistence*

herdr owns each agent's PTY. Hiding the float (or closing nvim entirely)
only detaches the nvim terminal — the agent keeps running in herdr. Float
mode places agents in a dedicated herdr workspace (default "herd.nvim"),
off your project workspaces/tabs; native mode places them as sibling tabs
in nvim's own workspace. To reattach after a restart:

- Run <leader>s (picker) or `:Herd select` — lists agents for the current project.
- Run `:Herd toggle` to reopen the float for the current project's agent.
- Use the dashboard (<leader>S or `:Herd dashboard`): float mode focuses the
  herd.nvim workspace; native mode opens the global cross-project agent picker
  (see |herd-native-mode|).

Agents are rediscovered via `herdr agent list`; as long as the herdr server
is running, sessions persist across nvim restarts.

==============================================================================
NATIVE MODE                                               *herd-native-mode*

`mode = 'native'` spawns an agent as a sibling herdr tab in nvim's own
workspace and focuses it via the herdr CLI, instead of an nvim floating
terminal. There is no nvim window (float or tab) for the agent — scrolling,
clicking, and drag-select are native Ghostty-over-herdr behavior.

Requires nvim to run inside a herdr pane (`$HERDR_TAB_ID` must be set);
otherwise `setup()` warns and falls back to "float" for the session.

Going to an agent is an nvim action (same keys as float mode). Coming back is
not — nvim isn't focused while herdr shows another tab, so it's ordinary
herdr tab/pane navigation instead: `last_pane` (if bound), `previous_tab` /
`next_tab`, or `next_agent` / `previous_agent`. Configure these in
`~/.config/herdr/config.toml`'s `[keys]` section, not in herd.nvim.

`bin/herd-return.lua`, run headlessly via `nvim -l`, adds a herdr-bound
round trip that knows which editor spawned the focused agent:

>toml
    [[keys.command]]
    key = 'prefix+\'
    type = "shell"
    command = "nvim -l /path/to/herd.nvim/bin/herd-return.lua"
<

Resolution is stateless, from live herdr state: the focused agent tab's
label (e.g. "dotfiles:claude_2" → the sibling tab labelled "dotfiles"),
falling back to matching the agent's spawn cwd against your editor panes.
When nothing matches (not a herd tab, editor gone) it shows a herdr
notification and does nothing. If the herdr server is unreachable, the
script exits silently without error — the keybind never surfaces a failure.

With `auto_return` enabled (default), going to an agent also arms an exit
watcher: if the agent process ends while you are looking at its pane, focus
jumps straight back to nvim's tab and the now-idle agent tab is reaped
(see |herd-config|). Returning to nvim by hand disarms the watcher.

In native mode, `:Herd dashboard` (or `keys.dashboard`) opens a picker
over every running agent across all projects — rows read
"dotfiles:claude_2  [working]  · dotfiles-config" — and selecting one
focuses its tab, flipping workspace when the agent lives elsewhere. Float
mode keeps the old behavior: focus the dedicated herd.nvim workspace. When
snacks.nvim is installed, the dashboard renders through Snacks.picker
(full-size, with a preview pane showing each agent's metadata and live
output); without it — or with `picker = "select"` — it falls back to
vim.ui.select. The project picker always uses the compact vim.ui.select.

Resurrect the editor ~                                       *herd-resurrect*

The pane nvim runs in survives quitting nvim as an idle shell, so the agent
keeps running and herd-return still resolves the origin tab — but plain
herd-return would drop you on that nvim-less shell. Add `--resurrect` to
the binding to have it offer to relaunch nvim in that same pane:

>toml
    command = "nvim -l /path/to/herd.nvim/bin/herd-return.lua --resurrect"
<

With nvim alive in the origin tab the flag changes nothing (silent focus,
no prompt). When nvim is gone, the focused shell pane prompts
`herd: no nvim here — resurrect? [Y/n]`: y relaunches the editor in place
(`$HERD_EDITOR` overrides the launched command, default `nvim`; restoring
the session is your nvim config's job — e.g. a resession/persistence
autoload), n leaves you at the shell.

==============================================================================
COMMANDS                                                      *herd-commands*

    :Herd [toggle|select|send|dashboard|diagnostics|jump]    default: toggle
    :Herd spawn <tool>

    :Herd diagnostics                                    *:Herd-diagnostics*
        Send the current buffer's LSP diagnostics to the active agent as
        one text block — a file header, then "line:col [SEVERITY] message
        (source)" per entry — and land in the agent to review/submit.
        No-op with a notice when the buffer is clean. No default keymap;
        bind `require('herd').diagnostics` if you want one.

    :Herd jump                                                  *:Herd-jump*
        Read the active agent's recent output, collect its `path:line(:col)`
        references — existing files only, deduped — into the quickfix
        list, and jump to the first. No default keymap; bind
        `require('herd').jump` if you want one.

==============================================================================
API                                                                *herd-api*

    require('herd').toggle()
    require('herd').select()
    require('herd').send()
    require('herd').diagnostics()
    require('herd').jump()
    require('herd').dashboard()
    require('herd').spawn(tool)

Public helpers, for a custom `send.context` formatter or your own wiring:

    require('herd').format_context(ctx)
        { path, ft, sline, eline, text } → the default "path:lines" +
        filetype-fenced block the wrapped send produces.
    require('herd').format_diagnostics(path, diags)
        vim.Diagnostic[] → the text block `:Herd diagnostics` sends.
    require('herd').parse_refs(text, base)
        Extract `path:line(:col)` references from text (relative paths
        resolved against `base`, dead paths dropped, deduped) as quickfix
        items { filename, lnum, col }.
